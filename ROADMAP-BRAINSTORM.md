# Wrench-Branch — Roadmap Brainstorm (2026-09-17)

Свежий раунд на замену потерянного списка из 30 идей. Цель та же:
"логово айтишников" — единый центральный продукт для IT-специалистов
(инструменты + обучение + активности), профили с реальным весом в
резюме, долгосрочно — партнёрства уровня Postman.

Не переспрашиваю то, что уже решено: interview simulator, маркетплейс
шаблонов/сниппетов, менторский маркетплейс, доска голосования за
фичи, отдельная юмор-лента, tool-scoped Q&A, платная сертификация,
структурированные learning-path — всё это уже отклонено/отложено
раньше и здесь не повторяется. Company pages — по-прежнему до 3000
юзеров (но ниже есть облегчённый вариант той же идеи). Push-уведомления
по стрикам — по-прежнему отложены (но ниже есть email-путь для той же
цели). Skill-badges — доработанная версия ниже, с учётом твоего
замечания про обход через AI.

## Community / репутация

1. **Skill-badges 2.0** — не просто "прошёл N задач" (легко прогнать
   через сторонний AI), а бейджи за то, что сложнее подделать:
   консистентный стрик, вклад в базу знаний, peer-эндорсменты (см.
   ниже). Доработка исходной идеи с учётом твоего возражения.
2. **Peer-эндорсменты навыков** — облегчённая версия LinkedIn
   endorsements, но завязана на реальную активность на сайте (можно
   эндорснуть только того, чей профиль ты видел / кто ответил на твой
   вопрос в базе знаний) — дешёвый, трудноспамируемый сигнал доверия.
3. **"Верифицированный сотрудник компании X"** — лёгкая версия company
   pages: компания подтверждает конкретный профиль как своего
   сотрудника, точечно, без полноценного каталога компаний — не нужно
   ждать 3000 юзеров, работает уже при первой сотне.
4. **Публичная лента активности в профиле** — решённые челленджи,
   опубликованные статьи в базу знаний, комментарии — превращает
   профиль в живое портфолио, это и есть "вес в резюме".
5. **Скачиваемая/шарабельная карточка профиля** (PNG/OG-картинка) —
   "покажи свой Wrench Score" в LinkedIn/резюме/подписи почты —
   дешёвый виральный цикл.
6. **Агрегированный Wrench Score команды** — НЕ shared workbenches
   (это ты уже отклонил), а просто read-only лидерборд среди
   профилей, которые сами согласились связать себя в "команду" —
   никакого совместного редактирования, только агрегированный вид.
7. **Комментарии под статьями базы знаний с репутацией** — мини-Q&A,
   но привязанное к конкретной курируемой статье, а не отдельный
   форум — не то же самое, что уже отклонённый tool-scoped Q&A.

## Экосистема инструментов / интеграции

8. **VS Code-расширение** — вызов инструментов Wrench (JSON
   formatter, JWT decoder и т.д.) прямо из command palette — ближе к
   рабочему процессу дева, чем вкладка браузера, и технически проще
   полноценного browser extension из твоего long-term списка.
9. **CLI (`npx wrench <tool> <input>`)** — создание mock-эндпоинта,
   запрос зарплатной статистики, форматирование JSON прямо из
   терминала/CI-скрипта — продукт становится частью реального
   workflow, а не только вкладкой браузера.
10. **Публичный API каталога инструментов** (rate-limited, бесплатный)
    — `curl .../api/tools/uuid` — "82+ инструментов" превращается в
    инфраструктуру, на которую можно опереться. Это и есть механизм,
    через который партнёрство с Postman вообще становится возможным —
    не через "мы сайт", а через "у нас есть API-поверхность".
11. **Публичный OpenAPI-спек + автогенерируемая Postman-коллекция для
    собственного API Wrench-Branch** — прямое дополнение к сегодняшнему
    импорту Postman-коллекций в Mock API, и буквально то, что
    потребуется как предпосылка для разговора с Postman.
12. **Slack/Discord-бот** (`/wrench mock create`, `/wrench salary qa
    senior`) — туда, где QA/dev-команды и так координируются.
13. *(переспрашиваю то, что раньше было "непонятная ценность")* —
    **GitHub Action для Mock API / Webhook Inspector** — поднять
    mock-эндпоинт или webhook-бин как шаг CI. Раньше "интеграция с
    CI" была абстрактной, тут — конкретный сценарий под конкретную
    уже готовую фичу, стоит пересмотреть с этим углом.

## Обучение

14. **"Босс-челлендж недели"** — один заметно более сложный еженедельный
    челлендж с отдельным лидербордом — другой ритм вовлечения, не
    дублирует дневной стрик.
15. **Сертификат прохождения трека в Trainer** (НЕ платная
    сертификация, которую ты отложил) — бесплатная шарабельная
    карточка "прошёл трек JS Fundamentals" — тот же виральный цикл,
    что и карточка профиля, почти без затрат на разработку.
16. **Онбординг-маршрут для новичка** — один осмысленный путь Trainer →
    пара инструментов → первый челлендж → настройка профиля — сейчас
    на сайте ~90 инструментов и несколько систем без предложенного
    порядка (закрывает IA-проблему из прошлого аудита под углом
    retention/активации).
17. **Трейнер-упражнения "в масштабе реального проекта"** — помимо
    коротких JS-дрилов, более длинное "почини сломанное мини-приложение"
    в песочнице Playground — мостик между Trainer и Playground, которые
    сейчас никак не связаны (это уже отмечалось в прошлом исследовании).

## Retention

18. **Email-доставка дайджеста** — дайджест уже есть на сайте, но
    работает только если человек сам зашёл; email-подписка — реальный
    рычаг удержания без AI и без инфры за пределами уже существующего
    контент-пула.
19. **"Продолжить с того места"** — на главной для залогиненного:
    недорешённый челлендж, недопройденный трек Trainer, давно не
    открытый Workbench.
20. **Еженедельный личный дайджест** ("на этой неделе решено 3
    челленджа, Wrench Score вырос с X до Y") — дёшево, без AI, чистая
    агрегация уже собранных данных.
21. **Отслеживание рефералов** — не маркетплейс, просто "кто пришёл по
    твоей ссылке на профиль" — привязывает рост к уже существующим
    профилям, без отдельной фичи-монстра.

## Контент / PR

22. **Публичный лидерборд Wrench Score** отдельной индексируемой
    страницей (не только срез в дайджесте) — вечнозелёная, шарабельная,
    SEO-страница.
23. **"Зарплаты QA/dev — срез рынка"** — авто-обновляемый отчёт на
    основе агрегатов уже существующего калькулятора зарплат — реально
    цепляющий контент для Reddit/Habr, который заодно продвигает сам
    калькулятор.
24. **Публичный changelog** — при таком темпе разработки простое "что
    нового" — и сигнал доверия (живой продукт), и готовый контент для
    Reddit/Telegram/Habr-продвижения, которое ты уже рассматриваешь.
25. **"Built in public"-подача** для планируемого PR-push — идёт в паре
    с changelog, материал уже есть в истории git, почти бесплатно.
26. **Встраиваемый бейдж/виджет профиля** (шире текущего
    README-бейджа) — "verified on Wrench-Branch" на личном сайте/в
    GitHub-профиле — тот же виральный механизм, что карточка профиля,
    но постоянно на виду, а не разовый шаринг.
